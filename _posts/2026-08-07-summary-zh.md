## [汇编慢指令精选清单](https://github.com/xoreaxeaxeax/asm-hall-of-shame) ⭐️ 8.0/10

开发者发布了 asm-hall-of-shame，一个在 GitHub 上整理汇编指令的仓库，收录那些看似简单却慢得惊人的指令。该项目包含计时测量结果，并规定了基准测试这些指令的规则。 该清单揭示了硬件与软件边界上反直觉的性能陷阱，对底层程序员、安全研究人员和系统工程师很有价值。相关 Hacker News 讨论指出，慢指令可能被固件陷阱捕获，从而暴露出看似简单操作背后隐藏的巨大开销。 该项目的规则规定，被陷阱捕获、模拟或虚拟化的指令只能对陷阱本身计时，而不能对处理程序计时。其中值得注意的条目包括对 ACPI I/O 端口的一次耗时 12 毫秒的写入，评论者怀疑这会陷入系统管理模式（SMM）；仓库还链接了相关项目 smiiiiiiiiiiiiiiii，该项目利用慢指令来破坏 SMI 处理机制。

hackernews · piotrgrabowski · 8月7日 18:01 · [社区讨论](https://news.ycombinator.com/item?id=49214098)

**背景**: 在现代 x86 处理器上，大多数汇编指令只需纳秒级时间即可执行，但有些指令可能触发固件级操作，耗时达毫秒级。系统管理模式（SMM）是一种高权限的 x86 运行模式，它会暂停正常执行流程，转而运行底层固件代码，通常用于电源管理或硬件控制。当指令访问特定 I/O 端口或执行特定操作时，CPU 可能陷入 SMM，从而引入在指令集层面完全不可见的巨大延迟。理解这些陷阱对于性能调优、逆向工程和安全研究都很重要。

## [Rust 查询引擎让 Postgres 分析快 300 倍](https://malisper.me/how-we-made-postgres-hundreds-of-times-faster-the-query-engine/) ⭐️ 8.0/10

本文详细介绍了一个基于 Rust 的查询引擎 pgrust，通过批处理、运算符融合和 SIMD，使 Postgres 分析查询速度提升高达 300 倍，同时强调通过形式化验证和模糊测试来保证正确性。 如果这些说法成立，pgrust 可能显著提升 Postgres 在分析场景的竞争力，而传统上它落后于 ClickHouse 或 DuckDB 等专用列式数据库。它还证明了具有强正确性保证的 Rust 替代方案是可行的，可能影响 Postgres 生态系统的查询执行方式。 该引擎名为 pgrust，使用 Rust 编写，面向 Postgres 上的分析负载，采用批处理而非逐行处理数据，将相邻运算符融合为单个循环，并利用 SIMD 指令实现并行。作者表示，通过形式化验证和差分模糊测试，已证明 1000 多个面向用户的函数与 Postgres 对应函数行为完全一致，相关证明见项目 proofs 目录。

hackernews · poly2it · 8月7日 11:00 · [社区讨论](https://news.ycombinator.com/item?id=49208535)

**背景**: PostgreSQL 是一种传统的基于行的关系数据库，一次处理一行查询结果——这种方式简单，但在扫描大量数据的分析型负载中速度较慢。向量化执行（即批处理）改为每次算子调用处理成百上千行数据，摊薄了解释器开销，使编译器能生成 SIMD 指令，用一条 CPU 指令同时对多个数据点操作。运算符融合将多个处理步骤合并到一个循环中，避免中间结果的物化，从而进一步提升性能。pgrust 是一个基于 Rust 的查询引擎，将这些技术应用于 Postgres，作者通过形式化验证 1000 多个函数与 Postgres 行为一致，并使用差分模糊测试来强调正确性。

## [据报道 2027 年内存产能已被预订一空，AI 需求是主因](https://www.ign.com/articles/ramageddon-continues-another-year-as-2027-memory-capacity-is-reportedly-sold-out) ⭐️ 8.0/10

据 IGN 报道，2027 年的内存产能据报道已被预订一空，这意味着该年度的 DRAM 和 HBM 供应已全部分配完毕。这延续了由 AI 需求激增推动的“内存末日”趋势。 这表明内存短缺将持续，影响 PC、服务器和消费电子产品的定价与供应。AI 对 HBM 的大量需求正在挤占传统 DRAM 的生产，可能导致整个行业成本上升。 在同一技术节点下，HBM3E 生产给定比特数所消耗的晶圆供应量大约是 DDR5 的三倍。HBM 生产的加速限制了非 HBM 产品的供应增长，因此连 2027 年的产能也已被预订一空。

hackernews · inigyou · 8月7日 07:58 · [社区讨论](https://news.ycombinator.com/item?id=49207236)

**背景**: 高带宽内存（HBM）是由三星、AMD 和 SK 海力士开发的 3D 堆叠式计算机内存接口，专为高性能计算中的高带宽和低功耗而设计。AI 加速器高度依赖 HBM，而由于 HBM 每比特占用的晶圆面积大于标准 DDR5，扩大 HBM 生产会减少可用于消费级内存芯片的产能。

sub2api v0.1.171 及之前版本被曝存在一个 CVSS 8.8 的高危 OAuth 账户接管漏洞。攻击者仅需知道受害者注册邮箱，无需密码、验证码或用户交互，即可将自己的 OAuth 身份绑定到受害者账户，从而完全控制其 API 密钥、账单余额与订阅配额。 该漏洞极为严重，因为仅凭一个邮箱地址、无需任何用户交互即可实现完全账户接管。sub2api 是一款开源的 AI API 代理，统一接入 Claude、OpenAI、Gemini 和 Grok 等订阅服务，因此受影响用户的 API 密钥和付费配额面临直接风险，应尽快升级至已修复版本。 该漏洞编号为 CVE-2026-27812，位于 OAuth pending session 交换流程中：existingUser 分支不校验密码和验证码，攻击者可将目标用户 ID 设为受害者并完成 OAuth 绑定。攻击成功后，攻击者每次 OAuth 登录都会解析为受害者账户，从而持久访问受害者的 API 资源和账单信息。

telegram · zaihuapd · 8月7日 14:59

**背景**: sub2api 是一个开源 AI API 代理，可将 Claude、OpenAI、Gemini 和 Grok 的订阅统一接入，让用户共享订阅成本并无缝使用原生工具。OAuth（开放授权）是一种开放标准，允许用户在不共享密码的情况下授权第三方应用访问其资源；若实现不当，授权流程可能被利用，将攻击者的身份绑定到受害者账户。在此漏洞中，易受攻击的 pending session 流程在绑定新的 OAuth 身份前未对已有用户进行重新认证。
